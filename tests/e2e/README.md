# orderpay-e2e — Playwright End-to-End Tests

Tests the **full running stack** through a real browser:
`browser → nginx → Next.js → WebApi → Keycloak → SQL Server`.

This is Phase 6, Step 10-B. It's a standalone Node project (separate from the
.NET `tests/DevIO.OrderPay.Tests`).

## Layout

```
tests/e2e/
  package.json
  playwright.config.ts        # baseURL http://www.localhost, serial, admin session by default
  specs/
    helpers.ts                # Keycloak login, API token, data seeding
    auth.setup.ts             # logs in admin + customer, saves browser sessions
    auth.spec.ts              # login → dashboard, unauthenticated redirect
    customers.spec.ts         # admin creates a customer; customer role is gated (AdminOnly)
    products.spec.ts          # admin creates + deletes a product
    orders.spec.ts            # admin creates an order (Pending badge) + updates status
  fixtures/
    .auth-admin.json          # saved session (gitignored, generated by auth.setup.ts)
    .auth-customer.json       # saved session (gitignored)
```

The `setup` project runs first and persists a logged-in session per role, so the
specs skip the Keycloak login form. The `customer` role and the unauthenticated
cases override `storageState` per spec.

## Run (containerised — recommended)

No host Node or host DNS needed. The runner shares nginx's network namespace, so
`127.0.0.1:80` is nginx and Host-based routing handles the three subdomains.

```bash
# from the repo root — the full stack must be up (docker compose up -d)
docker compose -f docker-compose.yml -f docker-compose.e2e.yml run --rm playwright
```

For CI / one-shot with an exit code:

```bash
docker compose -f docker-compose.yml -f docker-compose.e2e.yml \
  up --exit-code-from playwright --abort-on-container-exit playwright
```

## Run (host) — requires a Linux Node + `*.localhost` resolving to nginx

```bash
cd tests/e2e
npm install
npx playwright install chromium
npx playwright test          # headless
npx playwright test --ui     # interactive
npx playwright show-report   # HTML report after a run
```

## Notes

- **Why containerised?** The dev machine has only Windows Node via WSL interop, and
  Chromium hardcodes `*.localhost → 127.0.0.1`. Running inside nginx's netns sidesteps
  both. `/etc/hosts` is patched so Node (wait-on + the seeding fixture) resolves the
  subdomains too.
- **Seeding:** order specs seed a customer + product (and one order) via the API using a
  direct-grant token from the `orderpay-swagger` client; the order creation and status
  update themselves are driven through the UI.
- `fixtures/.auth-*.json` are generated at runtime and gitignored.
